# 通话权限引导与后台来电准备

日期：2026-11-17。范围为真实 App 的一对一 VoIP，普通消息继续 UniPush；沿用隐私同意、登录和现有测试／生产功能闸门。本设计不修改生产配置，也不把后台来电服务缺口归因于用户未开权限。

## 优先解决的 iOS 未闭环项

用户已报告：iPhone 清理后台进程后收不到语音邀请。此项仍未通过，不能被前台互拨或华为锁屏通过覆盖，也不能靠增加权限弹窗标记完成。

2026-11-17 本轮重新 fetch `nuwax-im/origin/feat-video-meeting`，HEAD 仍为 `0fa014fc86712a09bb9e321e24b5aa2dc4fc2ea0`。只读核对结果：

- `ImCallController` 仍提供 answered／ended／declined／meeting-invite-handled，没有当前客户端约定的电话设备注册入口。
- 所查分支未发现专用 APNs VoIP sender。后端 `docs/07-移动端APP对接文档.md` §9.3 明确说明 `voipToken` 可落库，但尚无发送使用方，原 R-07 决策仍将 VoIP Push 列为取消；这一范围需要随移动端电话需求更新。
- 客户端已有原生 launch restore、PushKit token 注册、原生系统来电及接听媒体逻辑。注册目标为 `POST /api/instant-message/calls/devices`，当前实现适用 iOS 17.4+；iOS 15–17.3 保持既有前台／普通通知能力。
- 既有测试环境接口未就绪记录见 [验收记录](voip-acceptance.md)。本轮仅更新源码核对，没有重测已部署接口、发送 APNs、修改后端或读取私钥；不据某个分支断言所有独立服务的部署状态。

Apple 说明 VoIP push 可启动或唤醒 App，并交给 PushKit 后报告系统来电；这与普通通知是不同机制。系统回收、用户上滑退出及重启后的行为必须分别留证，不能把普通推送的强退规则直接套用为 PushKit 结论。[Apple PushKit](https://developer.apple.com/documentation/pushkit)、[处理 VoIP push](https://developer.apple.com/documentation/pushkit/responding-to-voip-notifications-from-pushkit)

P0 闭环顺序：确认测试部署版本与等价接口 → 真机 PushKit token 条件登记／撤销 → 后端对本次呼叫发送 APNs VoIP → 手机无进程时 PushKit 回调 → 原生系统来电 → 接听／双向音频 → 挂断释放。设备登记和 sender 契约复用 [iOS 对接说明](voip-ios-push-handoff.md)，不重写已通的会议 RTC 或在线通话链路。

## 产品入口与提示时机

主入口为“我的 → 通话设置”。具体界面保持在 `features/voip/`，个人页只挂载入口组件；路由壳放现有分包。消息推送入口和通话设置都读取同一系统通知状态，避免出现两个互相矛盾的开关。

1. 首次隐私同意且登录成功后，静默检查通话相关状态；生产通话能力未开放时不自动展示本引导。
2. 确有用户可处理的缺项时，先展示一张说明卡或一个说明弹窗：“开启来电提醒，避免错过语音和视频通话”，按钮“检查通话设置”／“稍后”。用户点击后才进入设置清单；不连续弹出全部系统授权。
3. 麦克风在首次语音拨打／接听时申请，相机在首次视频操作时申请。设置页可由用户主动提前授权；检查状态不启动采集。
4. 用户点击“稍后”后沿用现有消息后台引导的 30 天冷却；手动入口始终可用。新增引导与现有通知流程共用弹窗调度，不能各自计时后叠加弹出。
5. 有通话、接听确认、隐私弹窗或其他系统授权进行时不插入引导。回到前台只刷新状态；不自动跳设置、不自动重拨、不恢复旧录音。
6. 权限被用户关闭时，入口显示对应状态；自动提示遵守冷却，不在每次打开 App 时强制重复。服务端未就绪只展示服务提示，不跳手机设置。

页面展示业务语言。APNs topic、推送 token、厂商 AppID、服务接口等只进入受控诊断，不显示在面向普通用户的操作流程中。

| 检查项 | 产品行为 | 不可误判的边界 |
| --- | --- | --- |
| 系统通知 | Android 使用适用系统授权；普通消息复用已有申请／设置入口 | iOS 普通通知授权不充当 PushKit 注册或送达的开关 |
| 来电分类 | Android 使用“音视频通话邀请通知”，高重要度默认值及铃声由 App 创建；可跳指定分类页 | 用户主动静音显示“已静音”，不擅自修改或反复创建渠道强行开声；不要求用户从零选择铃声 |
| 全屏展示 | Android 14+ 使用公开能力查询和系统专属设置页；低版本区分 manifest 声明与实际厂商行为 | API 31 上 manifest 权限已授予不能直接显示“锁屏全屏已验证” |
| 麦克风／相机 | 未决定时在明确操作后申请；被拒后提供 App 设置入口；语音不强制申请相机 | 锁屏首次接听需要授权时先引导解锁，不在锁屏下强行采集 |
| 自启动／电池策略 | 仅在本机通道、已知系统限制或失败诊断表明需要时给该机型建议；优先标准系统入口并提供返回路径 | 不让所有 Android 用户逐项放开全部设置；不能可靠读取的厂商项显示“待确认”，用户确认与系统检测分开保存 |
| 勿扰／响铃模式 | 显示本机状态和影响说明，用户自行决定是否改变 | 不绕过勿扰，不自动改变全局音量或响铃模式 |
| iOS 后台来电 | 普通消息和电话推送分别检查；PushKit 登记、sender 声明与实际呼入分别记录 | 不把“允许通知”或“后台 App 刷新”包装成修复未运行来电的必要开关；iOS 没有 Android 的自启动设置 |
| 服务未就绪 | “后台来电服务暂不可用”，保留已可用的在线通话，提供稍后重试 | 不提示用户反复授权、不把 mock 或 HTTP 200 当作真机送达 |

打开系统设置失败时回退到本 App 的系统设置页，并给出当前机型下的短路径说明。用户返回后重查可检测项，不能仅凭“打开过设置”或点击“我已设置”把状态变绿。

## 状态模型与当前代码缺口

按三层独立维护状态：

- **设备与用户选择**：适用性、授权状态、分类重要度／声音、系统模式；取值须支持 unknown、notApplicable 和用户主动关闭。
- **服务准备**：设备登记过程、登记回执及 sender 自报能力；与正在进行的通话生命周期分开。
- **实测证据**：最近一次前台／后台／锁屏／无进程呼入的结果与范围；只有真实证据才显示测试通过。

不能从任意一层推导“完整后台来电可用”。`registered=true` 仅表示设备登记，`nativePush=true` 仅为后端能力声明，不表示 APNs 已到手机。App 只应提示“设置已完成”或“服务已登记”，不能由此声称所有后台场景通过。

本轮已补：`callManager.uts` 的 `voipPushRegistration` 接收 session 级 `pushRegistration` 事件，即使还没有通话；只保存 provider、state、serverReady，不保存 token。状态包括 unknown、registering、registered、unavailable、configurationMissing、stopped；只有 registered 且原生报告 nativePush=true 时保留 serverReady=true。换账号／退出／更新原生会话后重置，旧 scope 回调忽略，注册失败不结束在线通话。

尚需实现：权限状态的统一读取接口、指定来电分类的设置跳转、可复用的引导调度、通话设置页面及四种语言文案。Android 已有 `getVoipPresentationStatus` 和全屏／App 设置跳转；iOS 当前该接口返回 unsupported，需要独立返回媒体授权和系统通话适用性，不能沿用 Android 的字段解释。

现有 `utils/push/pushBackgroundGuide.uts` 只在 Android 且识别为无厂商通道时提示，因此不能直接覆盖“已有华为／荣耀厂商通道，但来电分类／展示权限不全”的情况。复用其冷却与用户选择逻辑；通话缺项按自身状态判断，消息侧不改变发送／接收策略。
