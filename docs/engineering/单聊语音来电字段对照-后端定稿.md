# 单聊语音来电推送字段（后端对接稿）

2026-11-19 · 移动端提供字段契约，IM 后端同学负责实现投递分支。已存在的 `msgType="voip"` 及其邀请正文 `{callId, mediaType, roomName}` 继续用于发送和落库。本文约定的是 **IM 后端 → 云函数** 的请求，首轮覆盖**单聊语音**，包含 iPhone、华为安卓、荣耀安卓作为被叫。

## ① 当前 IM 的单条离线通知

以下两份 JSON 都只展示对接相关字段，使用同一条示例邀请。

```json
{
  "push_clientid": ["example-device-cid"],
  "title": "语音通话",
  "content": "张三邀请你语音通话",
  "payload": {
    "type": "voip",
    "convType": 1,
    "convId": "90001",
    "msgId": "80001"
  }
}
```

## ② 单设备原生来电请求

示例被叫设备为华为安卓。同一条邀请发给多个有效设备时，每台设备有自己的目标和路由，请求中的 `callId` 与消息定位相同。

```json
{
  "push_clientid": "example-device-cid",
  "title": "语音通话",
  "content": "张三邀请你语音通话",
  "callRoute": {
    "platform": "android",
    "transport": "android-huawei",
    "cid": "example-device-cid"
  },
  "payload": {
    "type": "voip",
    "convType": 1,
    "convId": "90001",
    "msgId": "80001",
    "callId": "73cf5bde-74e9-4412-8fa3-c7845542d1c6",
    "mediaType": "audio",
    "calleeId": "10002",
    "expiresAt": 1795050060000,
    "displayName": "张三"
  }
}
```

| 变化 | 字段 | 格式与来源 |
| --- | --- | --- |
| 原样复用 | `payload.type`、`convType`、`convId`、`msgId` | `"voip"`、整数 `1`、会话和消息 ID 的十进制字符串。用 `convId + msgId` 回查原邀请。 |
| 复用设备字段，原生入口改单设备 | `push_clientid`、`title`、`content` | `push_clientid` 用单个字符串，取服务端选中的被叫设备 CID，必须等于 `callRoute.cid`。`title`、`content` 保持字符串。 |
| **新增顶层对象，原生来电必传** | `callRoute` | 后端从被叫设备登记组装。所有子字段均为字符串，`cid` 为 1–128 位字母、数字、下划线或连字符。Android 的 `platform="android"`，`transport` 取 `android-huawei` 或 `android-honor`。iOS 定义见下节。普通消息和会议请求沿用原信封。 |
| **在现有 `payload` 补传** | `callId`、`mediaType` | 从原邀请正文复制。当前原生来电支持 1–128 位字母、数字、下划线或连字符组成的 `callId`，已有 UUID 可原样使用。首轮 `mediaType="audio"`。 |
| **在现有 `payload` 补传** | `calleeId`、`expiresAt` | `calleeId` 从原消息发送者和单聊关系取对端，以十进制字符串下发。`expiresAt` 取服务端原消息 `sendTime + 60000`，为 Unix 毫秒整数，重试沿用原截止时间。 |
| 展示字段，建议可选 | `displayName` | 从可信的主叫 `senderName` 映射，原生分支最多保留 80 个字符。若产品要求 iPhone 系统来电首屏展示主叫姓名，双方将其确认成必传。 |

**本轮交付是一个顶层对象 `callRoute`，加四个原生来电必传的 `payload` 字段。** 主叫发消息新增字段为零。接听时用 `convId + msgId` 回查原邀请里的 `roomName`，再按现有流程取 RTC 凭据。云函数按路由组装原生下行，Android 会附 `payload.delivery="android-native"`。

## 11 月 18 日联调与 VoIP 场景对齐

| 场景 | 字段怎样用 |
| --- | --- |
| 被叫在线 | 沿用 IM 消息帧和现有通话状态事件。在线与原生推送同时到达时，客户端按同一个 `callId` 去重。 |
| 锁屏或系统回收后收到单聊语音邀请 | 在有效期内，按被叫设备发送第 ② 份数据。验收核对同一 `callId` 的发送回执、原生回调和系统来电展示。 |
| 到期、取消、拒接或接听 | 到期按 `expiresAt` 判定。接听、拒接、取消沿用已有状态接口和事件，仍按当前邀请定位。 |
| 普通消息、会议邀请、群通话卡片 | 沿用既有消息/通知协议。第 ② 份原生来电首轮只用于单聊语音。 |

华为安卓的独立透传测试已观察到冷启动。真实拨号仍需通过同一 `callId` 验证原生通道和系统来电页。11 月 18 日红米拨 iPhone 16 时，实际云函数请求里已有 `type="voip"` 和 `msgId`，未带 `callRoute`、`callId`。同一个 CID 在 UniPush 返回 `20001 / target user is invalid`，设备状态查询没有记录。联调时先确认目标 CID 在对应应用下有效，再按这份字段验专用通道。

## iPhone 被叫补充（UniPush 路线）

`callRoute` 沿用同一顶层位置，`platform="ios"`、`transport="ios-voip"`、`cid` 仍取当前该设备的 UniPush CID，另外必传下面两项。两项均来自服务端已确认的 PushKit 登记。

| 字段 | 格式与来源 |
| --- | --- |
| `callRoute.environment` | 字符串 `development` 或 `production`，以被叫安装包的 APNs 签名环境为准。 |
| `callRoute.registrationId` | 当前有效的 PushKit 设备登记 UUID，使用小写标准格式。云函数下发为 `payload.routeRegistrationId`。 |

登记归属包含测试账号与设备、`bundleId="com.nuwax.app"`、APNs 环境以及已绑定 PushKit token 的 CID。后端可在现有设备登记上扩展，按登记版本处理更新与撤销。首轮按有效 CID 的实际投递与 PushKit 回调验收。
